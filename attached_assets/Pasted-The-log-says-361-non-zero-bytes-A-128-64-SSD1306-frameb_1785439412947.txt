The log says

361 non-zero bytes

A 128×64 SSD1306 framebuffer is 1024 bytes.

361 non-zero bytes is plenty for text.

So the text buffer isn't empty.

That means one of these is happening:

Possibility 1 (most likely)

The display is sleeping immediately after the flush.

Possibility 2

The framebuffer is being written to the wrong pages or columns.

The white test uses a completely different routine than the normal renderer, so it can work while the text renderer writes to the wrong memory addresses.

This happens surprisingly often when:

switching between SSD1306 and SSD1315
SH1106 vs SSD1306 addressing
page mode vs horizontal mode
column offsets (common on Heltec boards)
Possibility 3

The display is in inverted/page mode after the test pattern.

Less likely, but worth checking.
